# Forge performance review

Scope: all 39 skill entry points inventoried by size; targeted full reads of core routing, planning, brainstorming, frontend, coding standards, UI guidance, testing, reflection, Hub and commands. This was not an exhaustive execution test of all skills or bundled scripts.

| Finding | Change |
| --- | --- |
| Brainstorming forced repeated design approvals for defined tasks | Gate discovery on material uncertainty and reuse authorization |
| Plans duplicated full implementation and forced execution-choice prompts | Outcome-based plans, no full-code duplication, continue authorized execution |
| UI catalog imposed style and ran broad searches | User brief authoritative, domain-specific optional search |
| Coding examples loaded for routine changes | Compact default; detailed language examples on demand |
| Core repeated Hub schema and visual workflow | Delegate details to owning skill and keep routing in core |
| Testing treated available automation as a fresh dependency | Reuse authorized tools; ask only for actual additions |
| Reflection could read every skill | Targeted search and existing authorization |

Original material for four shortened skills is preserved verbatim in optional references. Historical blanket mandates are explicitly superseded by current entry points. References are not startup context.

Validation: skill packaging, Hub synchronization, changed Markdown links, original-text preservation, JSON/version consistency and whitespace checks. No real-project latency, model token count or artistic improvement measured. Word counts measure default instruction volume only; they do not predict total inference cost.

Remaining: large specialized entry points (canvas-design, project-hub, writing-great-skills) remain optional; avoid loading them for unrelated tasks. Validate installed-host behavior with a defined fix, open visual task and multi-step feature before claiming practical savings.
